# Bot 工作站功能完整性矩阵

本文件用于对照旧的 SongBot、MczMaker、Stable 与 Editor 工作流。工作站只整合入口与数据操作，不重写 MCZ 的高复杂度参数。

| 领域 | 已接入内容 | 数据与兼容边界 |
| --- | --- | --- |
| 运行中枢 | SongBot、NapCat 的启用、停用、端口与进程状态；五个可直接进入的功能模块 | “已启用”表示服务端口已就绪；工作站关闭不会自动停服；Ctrl+K 旁路已移除 |
| 谱面录入与图片设计 | 原 `MczTool` 菜单、拖放、谱面表格、Combo、BPM、音频试听、波形、截取、封面裁剪、图片设计、项目保存、日历设计 | 原组件整体嵌入并在启动后预热；不修改字体、字号、图片坐标、日历模板或计算参数 |
| Catch 写入 | Catch 独占完整键位块；空难度保持 `0-0`；不允许普通谱面污染 Catch 行 | 沿用 `CatchChartBlockAllocator` 与 `CatchChartRowMerger`，冲突时停止写入而非乱行 |
| 歌曲信息 | 全字段搜索、查看、新增、修改、删除；支持图片/音频上传 | 有本地库时事务同步 SQLite/CSV；无本地库时读取云快照并直接写云；删除同时释放 ID、清理该 ID 的媒体资源 |
| Stable 曲库 | 读取/编辑 Stable 全字段，调用原 Stable 抓取程序 | 有工作簿时同步 XLSX/CSV/SQLite 并备份回滚；便携端无工作簿时使用云端数据 |
| 每日歌曲与竞猜 | 调用原 `DailySongManager`，保留每日池、排期、竞猜与榜单底层数据 | 当前是否自动推送仍由 SongBot 配置决定，工作站不删除历史数据 |
| 公告管理 | 云端公告列表、新增/编辑/删除、时间、群号、图片、附件、置顶、成员确认、发送状态 | 复用原 `AnnouncementEditor`；云端为真源；已有待发送公告与附件继续使用原 ID |
| 公告模板 | 专辑模板、Event 模板、单曲模板、观影封面、观影定位 | 模板原文已补回桌面编辑器，UTF-8 保存 |
| 网站编辑 | teacharm.moe Markdown 云端列表、读取、导入、保存、删除、版本冲突保护、本机镜像 | 与公告共用受保护云存储服务，但使用独立 `website/` 数据域 |
| Editor 网站 | 正式站公开查歌，管理员编辑公告/附件/网站文章；点赞和访问统计由云端承载 | Vercel 承载静态页面，国内 FC 为主要 API，歌曲 JSON 与媒体经 CDN；正式站不再依赖本机 Funnel |
| 运营中心 | 每日歌曲与竞猜、Editor 正式站、RM Stable 抓取 | 不再重复 MCZ、歌曲信息、Stable、公告入口；抓取后引导回 Stable 曲库检查 |
| 手机端 App | 首次局域网配对、跨网络长期登录、分页歌曲/Stable 查询与编辑、图片/音频上传、应用内更新 | 曲库操作独立于电脑；8098 只用于首次私网配对；本机进程开关需主机后台代理在线；设备可撤销且受紧急阻断 |
| 便携工作站 | 在没有生产 SQLite/XLSX 的电脑上读取和编辑最新云曲库 | 首次自动注册受限 library-editor 设备；revision 缓存、gzip 快照回退、幂等新增/修改；不包含生产凭据 |
| 国内 API | 公告、网站、歌曲、Stable、设备、中继、点赞与访问的统一 Node handler | 阿里云 FC adapter 复用同一业务层；Vercel 保留静态托管和兼容部署，不再作为国内写入必经点 |
| 管理员权限 | 云端密码验证、可信 IP 指纹、网页 HttpOnly 会话、历史管理员设备白名单 | 密码只发送到受信任 HTTPS 验证端点且不落盘；原始 IP 不存储；普通曲库设备不能进入公告/网站管理；错误密码不封禁 |

## 不变量

- 未经管理员验证，不构造公告管理或网站编辑组件。
- 网站编辑桥接的每次读取、保存、删除与同步都再次检查管理员能力令牌。
- 云端公告和网站接口仍执行服务端鉴权；隐藏按钮不是安全边界。
- 不把 AccessKey、桌面令牌或机器人令牌写入 EXE、前端 JavaScript、日志或本文件。
- 左侧导航使用自绘矢量图标，不依赖可能缺字的字体图标；工作台多语言正文使用 Java 字形回退，MczMaker 原字体不变。
